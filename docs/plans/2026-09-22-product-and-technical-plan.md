# 心晴 Daylight：内容与技术实施方案

状态：提议方案，尚未开始功能开发。保留现有线上首页，本文档仅保存于本地。

## 产品目标

让用户在约 30 秒内完成一次情绪记录，并能基于自己的记录选择和完成一次关怀行动。主流程：记录 → 理解 → 选择行动 → 反馈 → 回顾。

面向学业、职场和社交压力下的年轻人。界面延续奶油白、鼠尾草绿、杏桃色与天气意象，避免排名和连续打卡惩罚。

## 内容与页面

| 页面 | 内容与操作 | 优先级 |
|---|---|---|
| 今日 | 当前心情选择、记录入口、近七日概览、一条可执行关怀建议、最近记录 | P0 |
| 日记 | 心情标签、总体感受 1—5、事件标签、可选文字、草稿、保存、编辑、删除；日历与列表切换 | P0 |
| 洞察 | 7/30 日情绪走势、情绪分布、常见事件关联、关怀练习反馈；可回看相关记录 | P0 |
| 关怀 | 呼吸引导、文字冥想、舒缓音乐和环境音、轻运动指引；开始、暂停、结束、感受反馈 | P0 |
| 设置 | 数据位置说明、导出/导入、清空确认、动画偏好、示例模式、AI 开关（接入后） | P0 |
| AI 解读 | 单篇记录解读、触发因素建议、行动推荐、每周回顾；用户主动触发 | P1 |
| 云同步 | 可选登录、跨设备同步、账号数据管理 | P2 |

桌面侧边栏，手机四个主导航（今日、日记、洞察、关怀），设置放头像/菜单入口。表单在手机上全屏显示。

记录允许同一天多次、混合情绪与自定义标签。总体感受用于趋势；情绪标签和强度分别保存，不把高强度直接解释为更差心情。文字不必填写。保存后可以结束，也可以进入关怀建议。

关怀内容初始目标：1 个呼吸工具、3 篇短文字冥想、3 段有明确使用许可的舒缓音乐、3 种环境音、3 套轻运动指引。音乐与环境音分开标识，音频由用户点击播放。记录来源与许可，音频随站点发布，不依赖不稳定外链。具体练习文案上线前单独核查。

## 分析与推荐策略

### 本地分析（首版）

- 图表和统计由真实记录计算；显示统计区间和记录数量。
- 日趋势取当日总体感受均值，点击能看到原始记录；无记录日期留空，不填零或插值。
- 触发因素先来自用户所选事件标签，展示共同出现次数和相关日记，不推断因果。
- 记录不足时显示原始统计与引导，不输出稳定规律。至少覆盖 5 天且有 7 条记录再展示跨日趋势摘要，此门槛属于产品规则。
- 推荐以情绪、可用时长、用户偏好和过往反馈筛选人工编写内容。最多推荐 3 项，并说明选择依据。
- 练习反馈采用更轻松/差不多/更难受，不保证改善。规则结果明确标为“根据记录整理”，不冒充模型输出。

### AI 解读（第二阶段）

输入：用户主动选择的一篇日记或指定时间范围摘要、情绪与事件标签、可用时长；发送前清楚说明内容和接收方。

处理：服务端验证会话、长度和配额 → 调用中文模型 → 校验结构化响应 → 关联已有关怀内容。

输出：简短共情、可能触发因素、关联原文、一个反思问题、关怀内容 ID。用户可以更正推测，结果不覆盖原始记录。

边界：不进行心理诊断，不把文本相关性表述为原因，不承诺疗效。出现明确即时危险内容时，停止普通建议，提示即时求助；具体资源按地区核实。

失败：超时、限流或格式不合格时明确提示，并提供本地规则建议；日记保存与练习继续可用。不自动反复重试产生费用。

## 推荐技术栈

| 层 | 选型 | 原因 |
|---|---|---|
| 页面 | React + TypeScript + Vite | 复用记录表单、卡片、图表和播放器；便于检查数据类型 |
| 样式 | CSS Modules + CSS 自定义属性 | 延续现有视觉；减少对大型后台组件样式的依赖 |
| 导航 | React Router 的 HashRouter | 静态托管中子页面刷新可用 |
| 图表 | Recharts | 绘制情绪折线、分布及趋势，并提供文字摘要 |
| 日期 | date-fns | 日历、周期筛选和本地日期展示 |
| 本地存储 | IndexedDB + Dexie | 保存多条结构化日记与练习记录，支持数据版本迁移 |
| 校验 | Zod | 校验导入文件、表单与 AI 返回内容 |
| 音频/练习 | HTMLAudioElement + CSS/SVG | 可控播放和轻量呼吸动效 |
| 发布 | GitHub Actions + GitHub Pages | 自动构建检查，通过后发布到现有网址 |
| 验证 | Vitest + Playwright | 验证统计、数据恢复及实际用户流程 |
| 后端（P1） | Supabase Auth + Edge Functions | 会话校验、模型调用、密钥管理与配额 |
| 云数据（P2） | Supabase PostgreSQL + RLS | 按用户隔离云端日记，支持跨设备同步 |

不引入独立全局状态库作为初始依赖；先用 React 状态和数据访问层管理。数据库操作、统计和模型接口与页面拆开，便于后续添加云同步。

## 数据设计

- JournalEntry：id、occurredAt、localDate、timeZone、overallMood、emotionLabels、emotionIntensity、triggerTags、body、createdAt、updatedAt。
- CareContent：id、类型、标题、时长、适用偏好、内容/音频路径、来源与许可。
- CareSession：id、contentId、关联日记 ID（可选）、开始时间、完成状态、练习前后感受。
- Insight：id、关联日记 ID、记录版本、来源（rule/model）、结果、生成时间。日记更新后旧解读标记失效；删除时清理关联解读。
- Preferences：动画偏好、关怀偏好、数据版本；AI 同意设置在接入时增加。

示例数据与个人数据使用独立存储空间；退出示例模式不带入个人统计。导入文件需检查版本、字段、大小及重复 ID，先展示导入摘要再应用。

默认仅保存在当前浏览器，不宣称已加密或已备份；清除浏览器数据可能丢失，提供 JSON 备份及 CSV 阅读导出。GitHub 仓库只存代码和公开内容，绝不存用户日记或模型密钥。

云同步启用时增加 user_id、版本号和删除标记；本地与云端发生并发编辑时保留两份供选择，避免静默覆盖。只有用户主动开启时才迁移本地记录。

## 部署实现

当前网址保持 https://1154057012.github.io/Daylight/。

Vite base 设为 /Daylight/；所有静态资源使用对应基础路径。GitHub Pages 从分支发布切换为 GitHub Actions；推送 main 后依次安装锁定依赖、校验类型、测试、构建、上传 dist 和部署。网页路由类似 /Daylight/#/journal。

GitHub Pages 为静态托管，不运行模型服务或数据库。AI 接口与云同步是外部服务，不影响网页仍通过当前 GitHub Pages 地址访问。AI 密钥只在服务端环境变量中；不能写入 VITE_ 变量后打包进网页。

Supabase 作为优先候选，在实际启用前检查用户所在网络的连通性、服务配额和可用模型凭据。限制来源仅作为附加措施；用户会话校验、配额和频率限制必须在服务端实现。日志不保存日记正文。

## 实施顺序与验收

1. 页面骨架与内容：替换占位页，完成桌面/移动布局、导航、空状态与独立示例模式；检查手机无横向溢出，所有操作有实际反馈。
2. 日记与存储：完成新增、修改、删除、草稿和备份；验证刷新保留、多次记录、中文内容、时区与存储失败不丢输入。
3. 分析与关怀：完成统计、内容筛选、真实音频、练习计时和反馈；验证数据修改后重算、空日期、播放暂停、切页停止音频与恢复计时。
4. 第一版发布：执行关键浏览器流程和构建检查，发布到现有链接并验证线上资源、子页面刷新及移动视图。
5. AI 接入：具备后端账号和模型凭据后完成结构化解读、明确同意、限额、失败回退与记录版本关联，再上线。
6. 云同步：按实际需求追加账号和数据库；验证用户隔离、导出与删除、并发冲突处理。

作品核心演示：新建一次情绪记录 → 保存并出现在日历/图表 → 查看事件关联 → 开始一个关怀练习 → 完成并反馈 → 刷新后查看保留的数据。
